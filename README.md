### 🎯

</td>
<td>

**The Problem**
Traditional clinics rely on paper records, phone-call bookings, and fragmented communication — resulting in missed appointments, lost medical histories, and an overall poor patient experience.

</td>
</tr>
<tr>
<td align="center">

### 💡

</td>
<td>

**Our Solution**
A unified digital platform offering appointment management, real-time doctor-patient chat, AI-driven specialty recommendations, electronic prescriptions, lab result tracking, WebRTC video consultations, and comprehensive medical records — all accessible from any device.

</td>
</tr>
<tr>
<td align="center">

### 🛠️

</td>
<td>

**Tech Stack**
`.NET 9` · `C# 12` · `SQL Server` · `EF Core 9` · `ASP.NET Identity` · `JWT` · `SignalR` · `WebRTC` · `FluentValidation` · `AutoMapper` · `Serilog` · `MailKit` · `ClosedXML` · `Swagger` · `xUnit`

</td>
</tr>
<tr>
<td align="center">

### 🌍

</td>
<td>

</td>
</tr>
</table>

<div align="center">

| Feature | Technology | Impact |
|:--------|:-----------|:-------|

| 💬 **Real-Time Chat** | SignalR WebSockets | Instant messaging with delivery & read receipts |
| 📞 **Video Consultations** | WebRTC Peer-to-Peer | HD voice & video calls between doctors and patients |

## 🏗️ 3 — Backend Architecture

The backend is structured as a **4-Layer Clean Architecture**. Each layer is a separate `.csproj` project with strict dependency rules — layers only reference the layer(s) below them.

<br/>

<div align="center">

```
╔═══════════════════════════════════════════════════════════════════╗
║                                                                   ║
║   🌐  API LAYER  (Presentation)                                  ║
║   ┊  19 Controllers · 3 Middlewares · ChatHub · Background Jobs  ║
║   ┊  10 DI Extension Classes · Filters · Validators             ║
║   ┊                                                               ║
║   ├──────────────────────────────────────────────────────────────┤║
║   ┊                                                               ║
║   ⚙️  BUSINESS LAYER  (Application Logic)                        ║
║   ┊  18 Services · 14 Validators · AutoMapper · Email Templates  ║
║   ┊                                                               ║
║   ├──────────────────────────────────────────────────────────────┤║
║   ┊                                                               ║
║   💾  DATA ACCESS LAYER  (Persistence)                            ║
║   ┊  DbContext · GenericRepository<T> · UnitOfWork · Seeders     ║
║   ┊  62 EF Migrations · Fluent API Configurations                ║
║   ┊                                                               ║
║   ├──────────────────────────────────────────────────────────────┤║
║   ┊                                                               ║
║   🧱  DOMAIN LAYER  (Core — Zero Dependencies)                   ║
║   ┊  20 Models · 51+ DTOs · 19 Interfaces · 6 Enums · Helpers   ║
║   ┊                                                               ║
╚═══════════════════════════════════════════════════════════════════╝
          ▲ Dependencies flow INWARD — Domain depends on NOTHING
```

</div>

<br/>

<details>
<summary><b>📂 Detailed Layer Breakdown (click to expand)</b></summary>

<br/>

| Layer | Project | Contents |
|:------|:--------|:---------|
| **🧱 Domain** | `DomainLayer.csproj` | 20 entity models (`ApplicationUser`, `Doctor`, `Patient`, `Appointment`…), 51+ DTOs organized in 8 domain folders, 19 service interfaces, 6 enums (`AppointmentStatus`, `CallStatus`, `DoctorVerificationStatus`, `MessageDeliveryStatus`, `PrescriptionStatus`, `GeneralEnum`), `Result<T>` wrapper, helpers & constants |
| **💾 Data Access** | `DataAccessLayer.csproj` | `ApplicationDbContext` with 18 Fluent API configs, `GenericRepository<T>`, `UnitOfWork` (14 repos), 62 EF Migrations, `PermissionSeeder` & `ApplicationUserSeeder` |
| **⚙️ Business** | `BusinessLayer.csproj` | 18 service implementations across 8 domains (`Auth`, `Doctor`, `Patient`, `Appointment`, `Clinical`, `Payment`, `Admin`, `Shared`), 14 FluentValidation validators, AutoMapper profile (20+ mappings), rich HTML email templates (47KB+) |
| **🌐 API** | `ClinicAPI.csproj` | 19 REST controllers organized in 5 areas (`Admin`, `Auth`, `Doctor`, `Patient`, `Shared`), `GlobalErrorHandling` + `LoggingAsyncMiddleware` + `SuperAdminAuthorizationHandler`, `ChatHub` (SignalR), appointment reminder background service, medicine Excel loader, 10 DI extension classes |
| **🧪 Testing** | `TestingLayer.csproj` | xUnit-based test project with service-level tests |

</details>

## ⚡ 10 — Getting Started

### 📋 Prerequisites

| Tool | Version | Required |
|:-----|:--------|:--------:|
| [.NET SDK](https://dotnet.microsoft.com/download) | 9.0+ | ✅ |
| [SQL Server](https://www.microsoft.com/en-us/sql-server) | 2019+ | ✅ |
| [Visual Studio](https://visualstudio.microsoft.com/) / [VS Code](https://code.visualstudio.com/) | Latest | 💡 Recommended |
| [Git](https://git-scm.com/) | 2.x+ | ✅ |

<br/>

### 🚀 Quick Setup

```bash
# 1️⃣  Clone the repository
git clone https://github.com/your-username/Tabibak.git && cd Tabibak

# 2️⃣  Restore NuGet packages
dotnet restore

# 3️⃣  Configure your environment
#     Update the connection string in API_Layer/appsettings.json
#     Set up your SMTP credentials for email features
#     Configure JWT secrets

# 4️⃣  Apply database migrations
dotnet ef database update --project DataAccessLayer --startup-project API_Layer

# 5️⃣  Run the application
dotnet run --project API_Layer
```
